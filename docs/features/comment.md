# コメント

- 日付: 2026-10-06
- 要件: [requirements.md](../requirements.md) の 3.6
- 設計: [api-conventions.md](../api-conventions.md)、[database-design.md](../database-design.md)
- Issue: 実装の順序の 8「コメントを作る」

## 1. 概要

投稿にテキストのコメントを付ける。書いた本人だけ消せる。編集はしない。入れ子にしない。投稿詳細に新しい順で並べる。

## 2. 画面（投稿詳細 `/posts/:id` の下部）

投稿詳細は、投稿のカード、コメントの節（`<section aria-label="コメント">`）の順に並ぶ。節の中は、フォーム、一覧の順。一覧が新しい順なので、書いた直後のコメントがフォームのすぐ下に見える。

### コメントフォーム

| 項目 | 入力 | 検証 | 誤りの文言 |
| --- | --- | --- | --- |
| 本文 | 複数行テキスト。残り文字数。名前は「コメント」（読み上げだけ）、例示は「コメントを入力」 | 1〜280 文字（空白だけは不可）。改行は LF に直してから数える | 1〜280 文字で入力してください |

- 入力欄は投稿フォームの `BodyField` を使う。名前と例示だけを props で変える。残り文字数と、超えたときの赤字は `BodyField` がすでに持っているので、作り直さない
- ボタン「コメントする」。空、超過、送信中は無効。全角空白や改行だけの本文も、画面（JS の `trim()`）が空として扱うので無効になる
- 成功したらフォームを空にし、誤りも消す。通知は出さない。一覧の先頭に自分のコメントが出て、投稿カードのコメント数が 1 増えるので、書けたことは見て分かるため
- 素早く 2 回送っても、送るのは 1 回だけ。ボタンの連打も、ボタンにフォーカスがあるときの Enter の連打も同じ（入力欄の Enter は改行なので送信にならない）。送信中を ref で見て止める（投稿フォームと同じ）。state だけで止めると、再描画の前に 2 回目が通るため
- 失敗しても入力は残す（404 だけは、ホームへ戻ってフォームごと無くなる）。書いた本人がフォームを見ているので、サーバーの文言で何が失敗したかを伝える（いいねの失敗が固定の文言なのは、押してすぐ別の所を見ていることが多いため。ここは事情が違う）
  - 422 で `body` の誤りがあれば、入力欄の下に出す。`body` の誤りが無い 422 は、`detail` をフォームの上に出す（投稿フォームと同じ）
  - 404 は「見つかりません」を通知し、その投稿を一覧のキャッシュから除いて、ホームへ戻す。書いている間に投稿が消された場合
  - それ以外（500 を含む）は `failureMessage` を通知する。500 は末尾に「（ID: <requestId>）」が付く
  - 送信中に画面を離れて失敗したときは、誤りを見せる欄が無いので、422 の文言も通知で出す

### コメント一覧

- 新しい順の無限スクロール。一覧の名前（`InfiniteList` の `label`）は「コメント一覧」。各行はアイコン、表示名、`@ユーザー名`、相対時刻、本文
- アイコンと名前はプロフィールへのリンク（44px 四方以上）。相対時刻は `<time>` で、マウスを載せると絶対時刻が出る（リンクにはしない）。行を押しても移る先が無いので、カード全体は押せるようにしない
- 本文は投稿と同じ `PostBody` で出す。`http://`・`https://` の URL をリンクにし、改行を保ち、HTML は文字のまま出す。URL の判定とリンクの安全な開き方を 2 か所で持たないため
- 本人のコメントだけ「削除」ボタン（`aria-label`「このコメントを削除」、44px 四方以上）を出す。確認ダイアログを経て消す
  - 確認は見出し「このコメントを削除しますか？」だけで、ボタンは「削除」と「取り消し」（取り消しが既定）。説明の段落は出さない（`ConfirmDialog` の `description` を省けるようにした。ほかの呼び出し元の見た目は変わらない）
  - 成功したら「コメントを削除しました」を通知し、一覧から除き、コメント数を 1 減らす（0 未満にはしない）。投稿の削除の通知「投稿を削除しました」とそろえた
  - 404（もう無い）は「見つかりません」を通知し、そのコメントを一覧から除いて、投稿詳細を読み直す。コメントだけ消えたのか、投稿ごと消えたのかが、この 404 だけでは分からないため。投稿ごと消えていれば、画面が「見つかりません」になる。このときコメント数は 1 減らさず、読み直した投稿の値に任せる
  - それ以外の失敗は `failureMessage` を通知し、一覧に残す
  - 素早く 2 回押しても、消す要求は 1 回だけ
- 0 件なら「まだコメントがありません」
- 一覧の読み込みの失敗は、`InfiniteList` の既定（再試行）のまま。一覧だけが 404 になるのは、投稿を読んでから一覧を読むまでに投稿が消されたときだけで、まれなため

### コメント数

- 投稿カードのコメント数の名前は「コメント n 件」。一覧（タイムラインとプロフィールの投稿一覧）のカードでは、投稿詳細へのリンクにする（44px 四方以上）。コメントを読み書きする場所は投稿詳細で、一覧のカードにはコメントの置き場所が無いため。プロトタイプも一覧ではリンクだった
- 投稿詳細の中では、今までどおり押せない表示（`role="img"`）にする。すぐ下にコメントがあるので、移る先が無い。どちらにするかは、`PostCard` の `linkToDetail` で決める

### 画面のキャッシュ

コメントを書いた・消したら、キャッシュにある同じ投稿の `commentCount` をまとめて 1 増やす（消したら 1 減らす）。対象はタイムラインとその人の投稿一覧の全ページと、投稿詳細。書いたカードだけを変えると、ホームへ戻ったときに一覧の数が古いままになるため。いいねの同期と同じ考え方。

- 数の書き換えは `changeCommentCountInCache` に 1 つにまとめ、成功のときに 1 回だけ呼ぶ。いいねと違い、同じ状態を何度書いても同じ、とはならない（2 回呼ぶと 2 増える）。404 で消せなかったときは呼ばない。数を含めた本当の状態が分からないので、投稿詳細を読み直して任せる
- コメント一覧のキャッシュのキーは `['comments', 投稿 id]`。書いたら 1 ページ目の先頭に足し（同じ id が既にあれば先に除く）、消したら全ページから除く
- 一覧を読み込んでいる最中の扱いは、[timeline.md](timeline.md) の「画面のキャッシュの書き換え」と同じ。データのある読み込みは、書き換える前に取り消す。取り消さないと、次のページの到着で、足したコメントが消えたり、消したコメントが戻ったりするため。最初の読み込みの最中なら、成功のあとで取り消して読み直す。まだ読んでいない一覧には何もしない（開いたときに最新が取れる）
- 投稿詳細は、投稿の id が変わると、コメントの節を作り直す（フォームの入力と一覧を、前の投稿から持ち越さない）

### 受け入れること

- 投稿詳細を開いている間に、他の人が書いたコメントは、読み直すまで出ない。通知や自動更新は作らない範囲のため
- 一覧の読み直しと数の増減が重なると、コメント数が一瞬ずれることがある。次の読み直しで直る

## 3. API

| API | 入力 | 応答 |
| --- | --- | --- |
| `GET /api/posts/{id}/comments` | cursor, limit | 200 Comment の一覧（新しい順）。404 |
| `POST /api/posts/{id}/comments` | `{ "body": "..." }` | 201 Comment。404、422 |
| `DELETE /api/comments/{id}` | | 204。403、404 |

## 4. 処理の流れ

- 投稿（`POST`）: 投稿の存在を先に確かめない。本文を検査してから `comments` に行を入れ、外部キー違反で投稿の有無を見分ける。先に確かめても、確かめてから入れるまでの間に消される場合は外部キー違反で扱うことになるので、経路を 1 つにした。そのため、本文が不正で投稿も無いときは 404 ではなく 422 になる。入れたあと `findById` で読み直して返し、無ければ（入れた直後に消された）404 にする
  - 外部キー違反は制約名で見分ける。`comments_post_id_fkey` は 404 `NOT_FOUND`（書く直前に投稿が消された）、`comments_user_id_fkey` は 401 `UNAUTHENTICATED`（退会と同時に書いた）。知らない名前は変換せず 500（[error-handling-design.md](../error-handling-design.md)）。制約名を調べる部分は、いいね・投稿・認証と共有の `ConstraintViolations`。名前から何にするかは、機能ごとに持つ
- 一覧（`GET`）: 投稿が無いのか 0 件なのかを区別するため、先に `PostMapper.existsById` で確かめて、無ければ 404 にする
- 削除（`DELETE`）: コメントを主キーで引き、無ければ 404。`user_id` がログイン中の利用者と違えば 403。同じなら消す。消した行数が 0 なら（引いたあとに別の要求で消された）404 にする
- 削除の出来事 `comment.deleted` を INFO で残す。項目は `app.comment.id` で、利用者 id は MDC が付ける。書いたときの出来事は足さない。[logging-design.md](../logging-design.md) の 3 章の表に無く、書いたことは要求ログ（`http.request`）で追えるため。本文はログに書かない
- 本文の規則は `CommentBodyRules.validate`。順序は投稿の `PostBodyRules` と同じ。(1) null は空文字 (2) 使えない文字（NUL・対になっていないサロゲート）は「使えない文字が含まれています」 (3) CRLF を LF に (4) `strip()` で空なら「1〜280 文字で入力してください」 (5) 280 コードポイントを超えたら同じ文言。返すのは (3) の後の値で、前後の空白は残す。誤りは `ValidationException`（項目は `body`）
  - 要求の型 `CreateCommentRequest` には `@NotBlank` や `@Size` を付けない。`@NotBlank` は `trim()` で判定するので、全角空白だけの本文を通してしまう。画面（JS の `trim()`）と投稿（`strip()`）は全角空白を空として扱うので、そろえた
- 応答の型は `CommentResponse(id, author, body, createdAt)`。`author` は UserSummary で、`avatarUrl` はアイコンのキーが null なら null、あれば URL に変換する。`email` と `password_hash` は読まない
- 一覧の区切り方: `limit + 1` 行を読み、あふれた分は返さず、`nextCursor` には返す最後のコメントの id を入れる。区切り方は `CommentService` の中に書く（`LikeService.likers` と同じ形）。投稿の一覧の `PostPages` と合わせて 3 か所になったが、共通化はフォローの一覧を作る Issue 9 で行うと、いいね（Issue 7）のときに決めてある
- 投稿の `commentCount` は、投稿を返すときに `comments` を数える。`PostAssembler` が、1 ページ分の投稿 id に対して 1 本の問い合わせで数え、無ければ 0 を入れる。1 ページの問い合わせは、本体・画像・いいね数・自分のいいね・コメント数の 5 本で、ページの件数によらない。空のページでは問い合わせない（[timeline.md](timeline.md) の 4 章）

## 5. データ

`V4__comments.sql` で `comments` を作る。索引 `(post_id, id)`。投稿を消すと連鎖で消える。

## 6. テストの期待一覧

### 正常系

- 投稿すると 201。`body`、`author`（自分）、`createdAt` が返る
- 一覧に新しい順で返る
- 投稿のあと投稿を取り直すと `commentCount` が 1 増える
- 本人が削除すると 204。一覧から消え、`commentCount` が減る
- 削除が出来事 `comment.deleted` として利用者 id とコメント id 付きで残る（[logging-design.md](../logging-design.md) の 3 章）
- 画面: 投稿した直後に自分のコメントが一覧の先頭に出て、フォームが空になる。通知は出ない
- タイムラインと投稿詳細の `commentCount` が、`comments` を数えた値になる。1 ページの問い合わせは 5 本で、ページの件数によらない
- 退会すると、本人のコメントと、本人の投稿へのコメントが消え、他人の投稿の `commentCount` が減る

### 入力の境界

- 1 文字は通る。空と空白だけは 422
- 280 文字は通る、281 文字は 422
- 改行を含む 280 文字が通る
- NUL 文字を含むと 422
- 見た目は空なのに文字がある本文: 全角空白だけ、改行だけの本文は 422「1〜280 文字で入力してください」。画面では送信ボタンが無効になる
- CRLF の混じった本文は、LF に直してから数える。LF に直して 280 文字なら通り、保存された本文の改行は LF

### 権限

- 未ログインは 401
- 他人のコメントを削除すると 403 で行は残る
- 投稿の持ち主でも、他人のコメントを削除すると 403
- 存在しない投稿へのコメントと一覧は 404。存在しないコメントの削除は 404

### 異常系

- 画面: 投稿に失敗しても本文は残る
- コメントの直前に投稿が消され、外部キー違反（`comments_post_id_fkey`）になったら 404 `NOT_FOUND`。500 にならない（Mapper の代役に外部キー違反を投げさせて確かめる）
- 本人への外部キー違反（`comments_user_id_fkey`。退会と同時に書いた）は 401 `UNAUTHENTICATED`
- 知らない名前の外部キー違反は変換せず 500。入れた直後に消されて読み直しが空なら 404
- Mapper（本物の DB）: 存在しない `post_id` で `comments` に入れると、外部キー違反の制約名が `comments_post_id_fkey` である（代役のテストが打つ名前と、本物の名前が合っていることを確かめる）
- 画面: 書いている間に投稿が消され 404 になったら、「見つかりません」が通知され、ホームへ戻る（フォームごと無くなるので、入力は残らない）
- 画面: 422 で `body` の誤りが返れば入力欄の下に出る。`body` の誤りが無い 422 は、`detail` がフォームの上に出る。どちらも入力は残る
- 画面: 404 と 422 以外の失敗は `failureMessage` が通知され、入力は残る。500 なら末尾に「（ID: …）」が付く
- 画面: 削除が 404 なら「見つかりません」が通知され、そのコメントが一覧から消え、投稿詳細が読み直される（数は 1 減らさない）。それ以外の失敗は通知され、コメントは一覧に残る

### 重複と一意性

- 画面: 送信中はボタンが無効で、二重送信されない
- 画面: ボタンを素早く 2 回押しても、ボタンにフォーカスがあるときに Enter を素早く 2 回押しても、`POST` は 1 回だけ
- 画面: 削除の「削除」を素早く 2 回押しても、`DELETE` は 1 回だけ

### 並び順とページング

- 一覧は id の降順。21 件なら `items` が 20 で `nextCursor` が 20 件目の id。`cursor` で続きが重複なく返る
- 続きの目印（`nextCursor`）のコメントが消されても、続きは欠けも重複も無く読める（200、残りの 1 件だけ、`nextCursor` は null）
- 投稿を削除すると、そのコメントがすべて消える（Mapper）
- 画面: 一覧の次のページを読み込んでいる最中に書いても消しても、届いたページで書き換えが上書きされない（足したコメントが消えない、消したコメントが戻らない）。最初の読み込みの最中に書いたら、成功のあとで読み直す。まだ読んでいない一覧には何もしない

### 画面

- 残り文字数が変わり、超えると送信できない
- 本人のコメントだけ「削除」が出る
- 本文の改行が保たれ、HTML は文字として表示される。`https://` の URL はリンクになる
- 削除の確認は見出し「このコメントを削除しますか？」だけで、説明の段落が無い。「取り消し」が既定のフォーカス。成功すると「コメントを削除しました」が出て、コメント数が 1 減る
- 一覧のカードのコメント数は「コメント n 件」の投稿詳細へのリンク。投稿詳細のコメント数は押せない表示（名前は同じ）
- 書く・消すと、タイムライン・その人の投稿一覧・投稿詳細にある同じ投稿のコメント数がまとめて変わる。0 未満にはならない
- 0 件なら「まだコメントがありません」
- アイコンと名前はプロフィールへのリンク。相対時刻は `<time>` で、絶対時刻が `title` に入る
- 投稿の id が変わると、コメントの節が作り直される

## 7. 手動確認の手順

1. 投稿詳細でコメントする → 一覧の先頭に出て、カードのコメント数が 1 増える。ホームに戻ると、同じ投稿のコメント数も増えている
2. 25 件以上コメントし、下までスクロール → 続きが読まれ、最後に「これ以上ありません」
3. 別のユーザーで開く → 他人のコメントに「削除」が出ない
4. 本人で削除 → 確認ダイアログ → 消え、「コメントを削除しました」が出て、数が 1 減る
5. タイムラインのカードのコメント数を押す → 投稿詳細へ移る。投稿詳細のコメント数は押せない
6. `docker compose stop backend` で backend を止めてからコメントする → 通知が出て、入力が残る（確かめたら `docker compose start backend`）
7. 別のタブで投稿を消してから、元のタブでコメントする → 「見つかりません」が出て、ホームへ戻る
8. 改行と `<b>太字</b>` と `https://example.com` を含むコメント → 改行が保たれ、`<b>` は文字のまま、URL はリンク
9. 360px 幅で、フォームと一覧が横にはみ出さず、「コメントする」と「削除」が押せる
