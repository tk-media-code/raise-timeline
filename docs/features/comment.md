# コメント

- 日付: 2026-10-06
- 要件: [requirements.md](../requirements.md) の 3.6
- 設計: [api-conventions.md](../api-conventions.md)、[database-design.md](../database-design.md)
- Issue: 実装の順序の 8「コメントを作る」

## 1. 概要

投稿にテキストのコメントを付ける。書いた本人だけ消せる。編集はしない。入れ子にしない。投稿詳細に新しい順で並べる。

## 2. 画面（投稿詳細 `/posts/:id` の下部）

### コメントフォーム

| 項目 | 入力 | 検証 | 誤りの文言 |
| --- | --- | --- | --- |
| 本文 | 複数行テキスト。残り文字数 | 1〜280 文字（空白だけは不可）。改行は LF に直してから数える | 1〜280 文字で入力してください |

- ボタン「コメントする」。空、超過、送信中は無効
- 成功したらフォームを空にし、一覧の先頭に自分のコメントが出る。投稿カードのコメント数が 1 増える
- 失敗したら通知を出し、入力は残す

### コメント一覧

- 新しい順の無限スクロール。各行はアイコン、表示名、`@ユーザー名`、相対時刻、本文
- 本人のコメントだけ「削除」。確認ダイアログを経て消す
- 0 件なら「まだコメントがありません」

## 3. API

| API | 入力 | 応答 |
| --- | --- | --- |
| `GET /api/posts/{id}/comments` | cursor, limit | 200 Comment の一覧（新しい順）。404 |
| `POST /api/posts/{id}/comments` | `{ "body": "..." }` | 201 Comment。404、422 |
| `DELETE /api/comments/{id}` | | 204。403、404 |

## 4. 処理の流れ

- 投稿: 投稿の存在を確かめ、`comments` に行を入れる
- 削除: コメントを主キーで引き、`user_id` がログイン中の利用者と同じときだけ消す。違えば 403
- 投稿の `commentCount` は `comments` を数える

## 5. データ

`V4__comments.sql` で `comments` を作る。索引 `(post_id, id)`。投稿を消すと連鎖で消える。

## 6. テストの期待一覧

### 正常系

- 投稿すると 201。`body`、`author`（自分）、`createdAt` が返る
- 一覧に新しい順で返る
- 投稿のあと投稿を取り直すと `commentCount` が 1 増える
- 本人が削除すると 204。一覧から消え、`commentCount` が減る
- 削除が出来事 `comment.deleted` として利用者 id とコメント id 付きで残る（[logging-design.md](../logging-design.md) の 3 章）
- 画面: 投稿した直後に自分のコメントが一覧の先頭に出る

### 入力の境界

- 1 文字は通る。空と空白だけは 422
- 280 文字は通る、281 文字は 422
- 改行を含む 280 文字が通る

### 権限

- 未ログインは 401
- 他人のコメントを削除すると 403 で行は残る
- 投稿の持ち主でも、他人のコメントを削除すると 403
- 存在しない投稿へのコメントと一覧は 404。存在しないコメントの削除は 404

### 異常系

- 画面: 投稿に失敗しても本文は残る

### 重複と一意性

- 画面: 送信中はボタンが無効で、二重送信されない

### 並び順とページング

- 一覧は id の降順。21 件なら `items` が 20 で `nextCursor` が 20 件目の id。`cursor` で続きが重複なく返る
- 投稿を削除すると、そのコメントがすべて消える（Mapper）

### 画面

- 残り文字数が変わり、超えると送信できない
- 本人のコメントだけ「削除」が出る
- 本文の改行が保たれ、HTML は文字として表示される

## 7. 手動確認の手順

1. 投稿詳細でコメント → 先頭に出て、コメント数が 1 増える
2. 25 件以上コメントし、下までスクロール → 続きが読まれる
3. 別のユーザーで開く → 他人のコメントに「削除」が出ない
4. 本人で削除 → 消える
