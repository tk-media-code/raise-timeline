# 投稿

- 日付: 2026-10-06
- 要件: [requirements.md](../requirements.md) の 3.3
- 設計: [image-storage-design.md](../image-storage-design.md)、[screen-design.md](../screen-design.md)、[error-handling-design.md](../error-handling-design.md)
- Issue: 実装の順序の 3「投稿とタイムラインを作る」（テキスト）、5「画像を扱う」（画像とビューア）

## 1. 概要

本文と 0〜4 枚の画像で投稿する。本文だけ編集できる。本人だけ削除できる。投稿詳細で 1 件とコメントを見る。

## 2. 画面

### 投稿フォーム（ホームの上部、または「投稿する」のダイアログ）

| 項目 | 入力 | 検証 | 誤りの文言 |
| --- | --- | --- | --- |
| 本文 | 複数行テキスト。残り文字数 | 0〜280 文字。画像が無いときは空白と改行以外の文字が 1 つ以上 | 280 文字以内で入力してください／本文か画像を入れてください |
| 画像 | ファイル選択（複数可）。プレビューと取り消し | 0〜4 枚。JPEG / PNG / GIF / WebP、1 枚 5 MB（5,242,880 バイト）まで。JPEG の GPS 情報は保存時に取り除く | 画像は 4 枚までです／画像は 5 MB 以内にしてください／JPEG、PNG、GIF、WebP の画像を選んでください |

- 欄の名前は「本文」（読み上げ用。見た目はプレースホルダー「本文を入力」）。残り文字数は「残り n 文字」で、超えたら「残り -1 文字」のように負の数で出し、赤くする
- ボタン「投稿する」。本文が空（空白と改行だけも空と同じ）で画像も無い、文字数超過、送信中は無効
- 本文が空白と改行だけ（全角空白を含む。Java の `strip()` で消える文字だけ）なら、サーバーも空と同じに扱う。画面は JS の `trim()` で判定するので、対象の文字が少し違う（両方向にずれる）。すり抜けても 422 で入力欄の下に出る。画像が無ければ 422「本文か画像を入れてください」。空白だけの投稿は、利用者から見れば空だから。字下げのように意図した空白は消したくないので、それ以外の本文は、前後の空白も含めて入力のまま保存する（直すのは CRLF を LF にすることだけ）
- 成功したらフォームを空にし、「投稿しました」の通知を出す。タイムラインの先頭に新しい投稿が出る（キャッシュを直接書き換える。[timeline.md](timeline.md) の 4 章）
- 失敗したら、422 は入力欄の下（`body` に紐付かないものは `detail` をフォームの上部）に出す。それ以外は通知を出す。どちらも入力は残す。通知の文言は [error-handling-design.md](../error-handling-design.md) の 5 章の表に従い、操作ごとの文言は作らない
- 「投稿する」のダイアログ（スマホは右下の丸ボタンから開く）の見出しは「新しい投稿」。閉じるボタンは「閉じる」（見た目は ×）
- 送信中でも、Esc・「閉じる」でダイアログを閉じられる。閉じたあとで送信が失敗したら、通知だけで伝える（入力は残らない）。成功したときの「投稿しました」は閉じていても出る。ブラウザが自分でダイアログを閉じたとき（Esc を重ねたときや、Android の戻る操作）も、画面の状態を合わせる。送信中は閉じさせない案は採らない。Chrome は `cancel` を止め続けられると強制的にダイアログを閉じる（Android の戻る操作も同じ）ので、画面の状態と食い違って成り立たないため

### 投稿カード

[screen-design.md](../screen-design.md) の 4 章。本人の投稿だけ右上にメニューが出る。メニューを開くボタンの名前は「この投稿の操作」で、中の項目は「編集」「削除」。

- いいね数とコメント数は、Issue 3 では押せない表示にする（`role="img"` で、名前は「いいね 0 件」「コメント 0 件」）。値は仮の 0。いいね（Issue 7）とコメント（Issue 8）が、値と操作を足す。Issue 7 では「いいね」を同じ名前のボタンに替える（[requirements.md](../requirements.md) の「Issue ごとの仮の振る舞い」）
- 一覧のカードは、余白や本文を押すと投稿詳細へ移る。リンク・ボタン・メニューを押したとき、文字を選んでいる最中は移らない。キーボードと読み上げは、時刻のリンクから詳細へ行く

### 編集ダイアログ

- 見出しは「投稿を編集」。本文の複数行テキストと残り文字数。画像は表示するだけで変えられない
- ボタン「保存」「取り消し」。本文が空（画像も無い）なら保存できない
- 本文が元と同じなら「保存」を押せない。押せると、中身が同じでも「編集済み」が付いてしまうため
- 成功したらダイアログが閉じ、カードの本文が変わって「編集済み」が付く。編集の成功は通知しない（閉じてカードが変わるのが答えなので）
- 送信中でも Esc・「取り消し」で閉じられる。閉じたあとで失敗したら通知だけで伝える（理由は投稿フォームと同じ）
- 失敗の動き: 422 は入力欄の下に文言を出し（`body` に紐付かないものは `detail` をフォームの上部に出し）、ダイアログは開いたまま。403 は通知を出してダイアログを閉じる。表示中のデータ（本文や一覧）は変えない（[error-handling-design.md](../error-handling-design.md) の 5 章の「画面の状態は変えない」は、データを変えないという意味）。404 は通知を出し、その投稿を一覧と詳細のキャッシュから除いてダイアログを閉じる（投稿詳細なら、ホームへ移る）。それ以外は通知を出し、入力は残して開いたままにする

### 削除の確認ダイアログ

- 「この投稿を削除しますか？ いいねとコメントも消えます」。ボタン「削除」「取り消し」。取り消しが既定
- 成功したら「投稿を削除しました」の通知を出し、カードが一覧から消える。投稿詳細で削除したらホームへ移る
- 削除が 404（もう無い）なら、通知を出してその投稿を一覧と詳細のキャッシュから除く

### 画像ビューア

[screen-design.md](../screen-design.md) の 4 章。

### 投稿詳細 `/posts/:id`

- 見出しは「投稿」。投稿カード（時刻は絶対時刻、いいね数を押すといいねした人の一覧へ）
- コメントフォームとコメント一覧（[comment.md](comment.md)）
- 存在しない投稿は「見つかりません」の画面。見出し「見つかりません」、本文「お探しの投稿やユーザーは見つかりませんでした」、リンク「ホームへ戻る」
- id が UUID でない（`/posts/abc`。API は 400）ときも、投稿が無い（404）ときと同じ「見つかりません」の画面にする。URL を打ち間違えた人にとっては、どちらも「無い」ため。それ以外の失敗は「読み込みに失敗しました」と「再試行」
- Issue 3 では、いいね数とコメント数は押せない表示で、コメントのフォームと一覧は出さない（Issue 7・8 で足す）

### キャッシュの書き換え

投稿・編集・削除が成功したら、一覧と投稿詳細のキャッシュを直接書き換える。取り直すと、無限スクロールで読み込んだ全ページを順に取り直してしまうため。書き換えと読み込みが重なるときの扱いは [timeline.md](timeline.md) の 4 章。

### 通知（トースト）

[screen-design.md](../screen-design.md) の 4 章。

| | 動き | 読み上げ |
| --- | --- | --- |
| 成功（「投稿しました」「投稿を削除しました」） | 4 秒で消える | `role="status"` |
| 失敗 | 自動では消えない。「閉じる」で消す | `role="alert"` |

失敗を消さないのは、500 の通知に出る requestId を、利用者が写し取れるようにするため。

## 3. API

### `POST /api/posts`

multipart/form-data。部品 `body`（テキスト）と `images`（ファイル、0〜4 個）。画像が無くても multipart で送る。

| 応答 | 場面 |
| --- | --- |
| 201 Post | 成功。`images` は送った順 |
| 422 `VALIDATION_ERROR` | 本文 281 文字以上、本文も画像も無い（本文が空白と改行だけも空と同じ）、使えない文字（NUL、対になっていないサロゲート）、画像 5 枚以上、空のファイル、読み取れない JPEG |
| 413 `FILE_TOO_LARGE` | 5 MB 超 |
| 415 `UNSUPPORTED_IMAGE_TYPE` | 形式違い |
| 503 `IMAGE_STORAGE_UNAVAILABLE` | 画像の保存先（S3）が設定されていない環境で、`images` の部品が 1 つでもある。本文の検査より先に判定する（Issue 5 まで） |

multipart は Issue 3 から使う（画像を足す Issue 5 で API の形を変えずに済む）。Issue 3 は画像の保存先をまだ持たないので、`images` に部品が 1 つでもあれば 503 を返す。黙って捨てると、画像が付いたと思った利用者に嘘をつくため。

### `GET /api/posts/{id}`

200 Post、404。

### `PATCH /api/posts/{id}`

```json
{ "body": "直した本文" }
```

200 Post（`edited` が true）、403、404、422。画像は変わらない。`body` が null や欠けているときも、空と同じに扱う（画像が無ければ 422）。判定の順序は 404、403、422（他人の投稿には、本文が不正でも 403）。

### `DELETE /api/posts/{id}`

204、403、404。

## 4. 処理の流れ

画像付き投稿は [image-storage-design.md](../image-storage-design.md) の 4 章。先に S3 へ上げ、DB の書き込みが失敗したら消す。
削除は DB を消してから S3 を消し、S3 の失敗は `image.delete_failed`（WARN）で応答は 204。

## 5. データ

`V2__posts.sql` で `posts` と `post_images` を作る。削除は `ON DELETE CASCADE` で `post_images`・`likes`・`comments` が消える。

## 6. テストの期待一覧

### 正常系

- 本文だけで投稿すると 201。`body`、`author`（自分）、`images` が空、`likeCount` と `commentCount` が 0、`likedByMe` が false、`edited` が false（`likeCount` と `commentCount` は Issue 7 と 8 で数えた値になる。それまでは 0）
- 画像 1 枚で投稿すると 201。`images` に URL が 1 つ。S3 の代役に `posts/<uuid>.<拡張子>` のキーと正しい Content-Type で渡る
- 画像 4 枚で投稿すると `images` が送った順に 4 つ。`position` が 0〜3
- 本文が空で画像だけの投稿は 201
- `GET` で同じ内容が返る
- 本文を編集すると 200 で `body` が変わり、`edited` が true、`updated_at` が進む。`images` は変わらない
- 削除すると 204。そのあと `GET` は 404。S3 の代役の `deleteAll` に画像のキーが渡る
- 削除すると、その投稿の画像の行も消える（Mapper）。いいねとコメントが消えることは Issue 7 と 8 で確かめる
- 削除が出来事 `post.deleted` として利用者 id と投稿 id 付きで残る（[logging-design.md](../logging-design.md) の 3 章）

### 入力の境界

- 本文 280 文字は通る、281 文字は 422。絵文字 1 つは 1 文字と数える
- 改行を 10 個含む 280 文字の本文が通る（multipart の CRLF を LF に直してから数えている）。同じ本文を `GET` で取ると改行は LF
- 本文が空で画像も無いと 422
- 本文が空白と改行だけ（全角空白を含む）でも、画像が無ければ 422「本文か画像を入れてください」。編集でも同じ。PATCH の `body` が null や欠けているときも 422。保存される本文は `''` になる
- 前後に空白のある本文（字下げなど）は、空白も含めて入力のまま保存される
- 画像 4 枚は通る、5 枚は 422
- 5 MB は通る、5 MB ＋ 1 バイトは 413
- 空のファイルは 422
- GPS 座標を含む JPEG を上げると、保存されたもの（S3 の代役に渡った内容）に GPS の情報が無い。Orientation=6 の JPEG を上げると Orientation が残る。PNG はそのまま
- SVG とテキストファイルは 415（拡張子を `.jpg` に偽装しても 415）。PNG / GIF / WebP は通る
- 編集で 281 文字は 422。編集で本文を空にすると、画像があれば通り、無ければ 422
- 本文に NUL 文字を含むと 422（投稿も編集も）。対になっていないサロゲート（JSON のエスケープ `\ud800` など）を含んでも 422「使えない文字が含まれています」。対になった絵文字は通る
- 先頭だけ JPEG で中身が壊れた画像は 422「画像を読み取れませんでした」（`errors` の `field` は `images`）。S3 の代役に何も渡らず、DB に行が無い
- id が UUID でない（`/api/posts/abc`）と 400 `BAD_REQUEST`

### 権限

- 未ログインで投稿・取得・編集・削除は 401
- 他人の投稿を編集すると 403 で本文は変わらない
- 他人の投稿を削除すると 403 で行は残る
- 存在しない id の取得・編集・削除は 404

### 異常系

- S3 への保存が 2 枚目で失敗したら 500。DB に行が無く、1 枚目のキーが削除される
- DB の書き込みが失敗したら 500。上げた画像のキーがすべて削除される
- S3 の設定が無い環境で画像付きで投稿すると 503 `IMAGE_STORAGE_UNAVAILABLE`。本文だけの投稿は通る。本文が不正（281 文字など）でも、`images` の部品があれば本文の検査より先に 503 になる
- 削除で S3 の削除が失敗しても 204 で、WARN の出来事 `image.delete_failed` が出る
- 画面: 投稿に失敗しても本文と選んだ画像は残る
- 投稿の書き込みが本人への外部キー違反（`posts_user_id_fkey`。退会と同時に投稿した）になったら 401 `UNAUTHENTICATED`。500 にならず、上げた画像のキーは削除される
- 画面: 存在しない投稿の URL と、id が UUID でない URL（`/posts/abc`）で、どちらも「見つかりません」の画面が出る
- 画面: 編集の保存が 403 なら、通知が出てダイアログが閉じ、カードの本文は変わらない。404 なら、通知が出てその投稿が一覧から消える
- 画面: 送信中にダイアログを閉じて、そのあと送信が失敗しても、通知が出る。成功したら一覧の先頭に出る

### 重複と一意性

- 画面: 送信中はボタンが無効で、二重送信されない

### 並び順とページング

[timeline.md](timeline.md) と [profile.md](profile.md)。

### 画面

- 残り文字数が入力に合わせて変わり、超えると「残り -1 文字」と赤く出て送信できない。空白と改行だけの本文も送信できない
- 編集ダイアログの「保存」は、本文が元と同じなら押せない。変えると押せて、元に戻すとまた押せない
- 成功の通知（「投稿しました」「投稿を削除しました」）は 4 秒で消え、失敗の通知は「閉じる」を押すまで残る。編集の成功は通知しない
- いいね数とコメント数が押せない表示で、名前が「いいね 0 件」「コメント 0 件」
- 画像を選ぶとプレビューが出て、取り消せる。5 枚目を選ぶと文言が出る
- 5 MB 超と SVG は選んだ時点で文言が出る
- 画像を押すとビューアが開き、Esc と「×」と背景で閉じる。複数枚は左右のボタンと矢印キーで移る。開いたときは押した画像
- 「編集」で本文が変わり「編集済み」が付く。「削除」は確認ダイアログを経て一覧から消える
- 本文の改行が保たれる。本文に HTML を書いても文字として表示される。URL がリンクになる
- 本文の `javascript:alert(1)` と `data:text/html,<script>` はリンクにならず、文字として出る
- URL の終わり: 末尾の `.` `,` `;` `:` `!` `?` `'` `"` `]` はリンクに含めない。末尾の `)` は、URL の中で `(` より `)` が多いときだけ外す（`(https://example.com)` は `)` を外し、`https://ja.wikipedia.org/wiki/X_(Y)` は残す）。この 2 つを末尾が変わらなくなるまで繰り返す（`).` など）。全角の文字（`。`、日本語）はリンクに含めず、そこで切れる

## 7. 手動確認の手順

1. 本文だけで投稿 → タイムラインの先頭に出る
2. 画像 4 枚で投稿 → 2×2 で表示される。S3 の開発用バケットに `posts/` のオブジェクトが 4 つある
3. 画像を押す → ビューアが開き、左右で移動、Esc で閉じる
4. 編集 → 本文が変わり「編集済み」が付く
5. 削除 → 一覧から消え、S3 のオブジェクトも消えている
6. 別のユーザーでログイン → 他人の投稿にメニューが出ない
7. スマホ幅で右下の丸ボタンからダイアログが開いて投稿できる。長い URL や長い英字の本文で横スクロールが出ない
8. 改行を含む 280 文字ちょうどの本文が投稿できる
9. スマホで撮った写真を上げ、S3 のオブジェクトをダウンロードして GPS の情報が無く、縦に撮った写真が縦のまま表示されることを見る
10. 10 MB の画像を選んだときに画面の文言が出る（サーバーまで届いた場合に 413 か接続切断かも見る）
