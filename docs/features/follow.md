# フォロー／フォロワー

- 日付: 2026-10-06
- 要件: [requirements.md](../requirements.md) の 3.7
- 設計: [api-conventions.md](../api-conventions.md)、[database-design.md](../database-design.md)
- Issue: 実装の順序の 9「フォローを作る」

## 1. 概要

他の人をフォローする・解除する。承認は要らない。自分自身はフォローできない。フォロー中とフォロワーの一覧を見られる。
フォローすると、その人の投稿が「フォロー中」のタイムラインに出る。

## 2. 画面

### フォローボタン（プロフィール、ユーザーカード）

- 未フォロー: 青地に白の「フォロー」。フォロー中: 白地に枠の「フォロー中」。マウスを載せると、赤い枠・薄い赤の背景・赤い文字の「解除」になる（プロトタイプの `.follow-btn-on:hover` と同じ）。文字の大きさは 14px（`text-sm`）
- 「解除」は「フォロー中」の上に重ねて出し、ボタンの幅は「フォロー中」が決める。マウスを載せても幅が変わらない（幅が縮むと、右端に置いたボタンの左端がポインタの下から外れ、ホバーが切れて表示がちらつくため）。幅の下限は「フォロー中」の幅（全角 5 文字 + 左右の余白 2rem + 枠 2px）にそろえ、「フォロー」でも「解除」でも同じ幅にする。文字を 14px にしたので、この式はちょうど 104px になり、プロトタイプの 104px と同じ。文字が 16px のときは、同じ 104px が「フォロー中」より約 10px 狭く、解除すると縮んで、右端のボタンの左端が動いた（解除直後にその帯を押し直すとユーザーカードの `<article>` に当たり、プロフィールが開く）。幅の式を変えずに文字を小さくして、プロトタイプにそろえた
- 押した直後は、マウスが離れるかフォーカスが外れるまで「解除」を出さない。押した瞬間に「解除」と出ると、解除してしまったように見えるため
- 解除の前に確認は挟まない。間違えてもすぐ押し直せる
- 名前（`aria-label`）は、未フォローが「{表示名}さんをフォロー」、フォロー中が「{表示名}さんをフォロー中（押すと解除）」。「解除」の文字は読み上げに出さない
- 自分には出さない
- 押すたびに見た目をすぐ変え、API の要求は 1 つずつ送り、最後に押した状態に落ち着かせる（いいねと同じ仕組み。`useOptimisticToggle` を共用する）。連打しても、相手の「フォロワー n」は 1 しか増えない
- 失敗したら、サーバーに最後に保存できた状態に戻し、並んでいた分は送らずに捨てて通知する。通知は「フォローに失敗しました。もう一度お試しください」「フォローの解除に失敗しました。もう一度お試しください」。500 で requestId があれば「（ID: …）」を添える
- 404（相手が退会済み）は「見つかりません」を通知し、ユーザーカードの一覧からその人のカードを除く。相手のプロフィールのキャッシュは読み直しの対象にするので、開いていれば「見つかりません」の画面になる

### フォロワー `/users/:username/followers`、フォロー中 `/users/:username/following`

- プロフィールの数（「フォロー中 n」「フォロワー n」）を押すと移る
- 見出し（h1）はその人の表示名。スマホ幅の上部バーの画面名は「フォロー中」「フォロワー」で、誰の一覧かは出ない
- 見出しの下に、2 つの一覧を切り替えるタブ。並びは「フォロー中」「フォロワー」（プロフィールの数と同じ並びで、プロトタイプの逆）。タブの並びの名前は「フォロー中とフォロワー」。ホームのタブと同じ見た目の部品（`TabNav`）を使う
- ユーザーカードの無限スクロール。新しい順。カードは「いいねした人」と同じ部品で、右端にフォローボタンが付く（自分には出さない）
- 一覧は、その人のプロフィールが取れてから引く。いない人で 404 を 2 回出さないため。プロフィールが無ければ（404、規則に合わない名前）「見つかりません」の画面
- 0 件なら「誰もフォローしていません」「フォロワーはいません」
- スマホ幅で右下の「＋」を出す画面では、`<main>` の下の余白を `pb-16` から `pb-36` にし、一覧の最後のカードのフォローボタンが「＋」に隠れず、上までスクロールできるようにする（いいねした人の一覧も同じ）

### プロフィールの数

- 「フォロー中 n」「フォロワー n」は 1 つの文字列で、押すとそれぞれの一覧へ移る
- フォロー・解除すると、相手のプロフィールの `isFollowing` と「フォロワー n」（±1）をすぐ変える。ユーザーカードの一覧（いいねした人・フォロワー・フォロー中）にいる同じ人の `isFollowing` も、すぐ変える
- 次の 4 つは、要求が全部終わってから、画面に出ていなければキャッシュを捨て、次に開いたときに読み直す。ホームの「フォロー中」、相手のフォロワー一覧、自分のフォロー中一覧、自分のプロフィール（自分の「フォロー中 n」が変わるため）。画面に出ているものは触らない。中身が変わる一覧を表示中に読み直すと、押したカードが消えて押し直せなくなるため
- 受け入れること: 他の人がフォロー・解除したことによる数の変化は、読み直すまで出ない。相手のプロフィールの「フォロワー n」の ±1 と読み直しが重なると、数が一瞬ずれることがある（次の読み直しで直る）。通知や自動更新は作らない

## 3. API

| API | 応答 |
| --- | --- |
| `PUT /api/users/{username}/follow` | 204。既にフォロー中でも 204。自分自身は 422。404 |
| `DELETE /api/users/{username}/follow` | 204。フォローしていなくても 204。404 |
| `GET /api/users/{username}/followers` | 200 UserCard の一覧（新しい順）。404 |
| `GET /api/users/{username}/following` | 200 UserCard の一覧（新しい順）。404 |

## 4. 処理の流れ

- フォロー: 相手を `username` で引く（`UserService.requireByUsername`。居なければ・規則に合わなければ 404）。自分自身なら 422（`FieldError("username", "自分自身はフォローできません")`）で、行は入れない。そうでなければ `follows` に `(follower_id = 自分, followee_id = 相手)` を `INSERT ... ON CONFLICT (follower_id, followee_id) DO NOTHING` で入れる。既にあれば何もせず 204（一意制約の違反でトランザクションを中断させない）
- 外部キー違反は制約名で見分ける。相手を引いてから入れるまでの間に相手が退会すると `follows_followee_id_fkey` に違反するので、404 `NOT_FOUND`。自分が同時に退会すると `follows_follower_id_fkey` に違反するので、401 `UNAUTHENTICATED`。知らない名前は変換せず 500（[error-handling-design.md](../error-handling-design.md)）。いいねと同じ
- 解除: 相手を引き（404）、行を消す。無くても 204。自分を指しても 204
- ユーザー名は大文字小文字を区別せず引く（`PUT /api/users/ALICE/follow` も `/users/Alice/followers` も alice を指す）。規則（`^[A-Za-z0-9_]{3,20}$`）に合わない名前は DB に問い合わせずに 404、`%00` は Spring Security のファイアウォールが先に弾いて 400。どちらも 500 にならない（[profile.md](profile.md) の 2 章と同じ）
- 一覧: フォロワーは `followee_id = その人`、フォロー中は `follower_id = その人` で引き、`users` と結合する。各行の `isFollowing` は「ログイン中の利用者がその行の人をフォローしているか」
- 一覧の並びとカーソルは `follows.id`。`nextCursor` には `follows.id` を入れ、画面はそのまま送り返す。各行の `isFollowing` は `EXISTS` の副問い合わせで取る（[database-design.md](../database-design.md) の 5 章）。いいねした人の一覧と同じ行の型（`UserCardRow`）と変換（`UserCards.of`）を使う
- 一覧の区切り方は `Pages.of`（`limit + 1` 行を読んで渡す）。タイムライン・プロフィールの投稿・いいねした人・コメントの一覧と共用する
- プロフィールの数は `FollowMapper.stats(userId, viewer)` の 1 本で取る。`followersCount` と `followingCount` を副問い合わせで数え、`isFollowing` を `EXISTS` で取る。他人のプロフィール（`UserDetail`）と自分のプロフィール（`Me`）の両方で使う。`Me.isFollowing` は常に false（自分はフォローできない）。件数は読み出すときに数える（[database-design.md](../database-design.md) の方針 3）

## 5. データ

`V5__follows.sql` で `follows` を作る。一意 `(follower_id, followee_id)`、チェック `follower_id <> followee_id`、索引 `(followee_id, id)` と `(follower_id, id)`。

「フォロー中」のタイムラインは [timeline.md](timeline.md)。

## 6. テストの期待一覧

### 正常系

- フォローすると 204。相手のプロフィールの `isFollowing` が true、`followersCount` が 1 増え、自分の `followingCount` が 1 増える
- 解除すると 204。それぞれ戻る
- フォロワー一覧に、フォローした人が新しい順に UserCard で返る
- フォロー中一覧に、フォローしている人が新しい順に返る
- フォローすると、その人の投稿が「フォロー中」のタイムラインに出る。解除すると出なくなる

### 入力の境界

- 自分自身をフォローすると 422 `VALIDATION_ERROR`（項目は `username`、文言は「自分自身はフォローできません」）で行は増えない。大文字のユーザー名で指しても同じ
- 自分を指した解除は 204 で何も起きない
- 規則に合わないユーザー名（21 文字、日本語、空白）は 4 つの API とも 404。`%00` を含む名前は 400 で、500 にならない
- 一覧が 0 件なら `items` が空で `nextCursor` が null。21 人なら `items` が 20 で `nextCursor` が 20 件目の `follows.id`

### 権限

- 未ログインは 401
- 存在しないユーザー名は、フォロー・解除・フォロワー・フォロー中の 4 つとも 404

### 異常系

- 画面: API が失敗したら、ボタンと数が元に戻り、通知が出る。連打の途中で失敗したら、サーバーに保存できた状態に戻り、並んでいた分は送られない
- 画面: 404（相手が退会済み）なら「見つかりません」を通知し、一覧からカードを除く。プロフィールなら「見つかりません」の画面になる
- 画面: フォロワー／フォロー中の画面で、プロフィールを読んだあとに一覧が 404（持ち主が退会した）になったら、「再試行」ではなく「見つかりません」にする
- フォローの直前に相手が退会し、相手への外部キー違反（`follows_followee_id_fkey`）になったら 404 `NOT_FOUND`。自分への違反（`follows_follower_id_fkey`。自分が同時に退会した）は 401 `UNAUTHENTICATED`。どちらも 500 にならない

### 重複と一意性

- 2 回フォローしても `follows` は 1 行で、2 回目も 204
- フォローしていない人を解除しても 204
- A が B をフォローしても、B が A をフォローしたことにはならない（向きがある）
- 同じ人が同じ相手を同時に 2 回フォローしても、両方 204 で `follows` は 1 行

### 並び順とページング

- 一覧は `follows.id` の降順。`nextCursor` は 20 件目の `follows.id` で、`cursor` に付けると続きが重複なく返る
- 一覧の `isFollowing` は、見ている人がその行の人をフォローしているか（相手が自分をフォローしているかではない）
- 続きの目印（`cursor`）の行の人が解除しても（フォロワー一覧・フォロー中一覧とも）、続きは欠けも重複も無く返る
- 大文字小文字の違うユーザー名（`ALICE`、`Alice`）で、同じ人のフォロー・一覧になる

### 画面

- 押した瞬間にボタンが「フォロー中」になり、プロフィールのフォロワー数が 1 増える
- フォロー → 解除 → フォローを、要求の完了を待たずに押すと、最後に押した状態に落ち着き、フォロワー数は 1 しか増えない
- 自分のプロフィールとユーザーカードにフォローボタンが出ない
- 名前（`aria-label`）が、未フォローは「{表示名}さんをフォロー」、フォロー中は「{表示名}さんをフォロー中（押すと解除）」。押した直後は、ポインタが離れるかフォーカスが外れるまで「解除」が出ない
- 他人をフォローすると、自分のプロフィールの「フォロー中 n」が読み直されて 1 増える。自分のフォロー中一覧を表示中に解除しても、カードはその場に残って「フォロー」に戻り、開き直すと消える
- フォロワー／フォロー中の画面: タブは「フォロー中」「フォロワー」の順で、上部バーの画面名が変わる。大文字小文字の違うユーザー名の URL でも、同じキャッシュを使う

## 7. 手動確認の手順

スマホ幅（360px）も含めて、開発環境のブラウザで確かめる。

1. 他人のプロフィールでフォロー → ボタンが「フォロー中」に、「フォロワー n」が 1 増える。リロードしても保たれる
2. 自分のプロフィールを開く → 「フォロー中 n」が 1 増えている
3. 数を押す → フォロワー／フォロー中の画面に移り、正しい人が出る。タブは「フォロー中」「フォロワー」の順で、上部バーの画面名も変わる
4. ホームの「フォロー中」に相手の投稿が出る。解除すると出なくなる。「すべて」に切り替えると URL が `?tab=all` になり、リロードしても保たれる。`/?tab=foo` は「フォロー中」
5. フォローボタンを素早く何度も押す → 最後に押した状態に落ち着き、リロードしても同じ。フォロワー数が 2 以上ずれない
6. `docker compose stop backend` で backend を止めてからフォロー → 元に戻り、「フォローに失敗しました。もう一度お試しください」が出る（確かめたら `docker compose start backend`）
7. 別のタブで相手が退会してから、元のタブでフォロー → 「見つかりません」が出て、プロフィールが「見つかりません」の画面になる
8. 自分のフォロー中一覧で解除 → カードはその場に残り「フォロー」に戻る。画面を離れて開き直すと消えている
9. PC でフォロー中のボタンにマウスを載せる → 「解除」になる（幅は変わらない）。押した直後は、マウスを離してから載せ直すまで「解除」にならない
10. 360px 幅で、いいねした人・フォロワーの一覧の最後のカードのフォローボタンが「＋」に隠れずに押せる。長い表示名でも横にはみ出さない
