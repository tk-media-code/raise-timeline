# プロトタイプ（仕様確認用）

- 日付: 2026-10-06

`docs/` の仕様を、画面を触って確かめるためのクリックスルーのプロトタイプ。HTML / CSS / JavaScript だけで作ってあり、ビルドも依存も無い。**使い捨てで、本番の実装ではない。** ここで見つけた仕様の穴や食い違いは `docs/` に戻して直す。

## 開き方

次のどちらか。

- `prototype/index.html` をダブルクリックしてブラウザで開く（`file://` で動く）
- `prototype/` を HTTP で配信して開く

```bash
cd prototype
python3 -m http.server 8000
# http://localhost:8000/ を開く
```

URL は `#/` で始まるハッシュ（`index.html#/users/alice`、`#/search?q=ali`、`#/?tab=all`）。`file://` にはパスを解決するサーバーが無いのでハッシュにしてある。本物のアプリはパス（`/users/alice`）を使う。画面とパスの対応は `docs/screen-design.md` 1 章の表と同じで、先頭の `/` が `#/` に変わるだけ。

ファイルは次のとおり（読み込む順）。

| ファイル | 中身 |
| --- | --- |
| `store.js` | データ（`localStorage`）、見本データ、API の代わりの関数、検証 |
| `ui.js` | 共通部品（アバター、投稿カード、ユーザーカード、無限スクロール、通知、確認ダイアログ、画像ビューア、時刻の整形） |
| `views.js` | 画面ごとの描画 |
| `app.js` | ルーター、ログイン状態による振り分け、レイアウト |
| `styles.css` | スタイル（スマホ基準。768px 以上で PC の配置） |

## データの初期化

データはブラウザの `localStorage`（キー `rt.data`）に入る。ブラウザごと、オリジン（`file://` と `http://localhost:8000` は別）ごとに別。投稿・フォロー・登録は、このブラウザの中だけに残る。

見本データに戻すには、次のどれか。

- **PC**: 左ナビの「見本データに戻す」
- **スマホ幅**: 上部バー右の ≡ メニューの「見本データに戻す」
- ブラウザのコンソールで `RT.store.reset()`（画面が壊れて上の入口に届かないとき）。それでも直らないときは `localStorage.clear()` してリロードする

戻すとログアウトされ、ログイン画面に移る。

## 再現していること

- 仕様にある画面一式: 登録、ログイン、ホーム（フォロー中／すべて）、投稿詳細、いいねした人、プロフィール、フォロワー／フォロー中、プロフィール編集、検索、見つかりません
- 投稿（本文 280 文字、画像 4 枚まで）、編集、削除、いいね、コメント、フォロー、検索
- 入力の検証と、`docs/features/*.md` の誤りの文言
- 一覧の 20 件ずつの読み込み（末尾が見えたら次を読む）、終端「これ以上ありません」、失敗時の「再試行」
- いいね・フォローの楽観的更新（押した瞬間に見た目を変え、保存は少し遅れる）。連打しても最後の状態に収束する
- 時刻の表示規則（`docs/screen-design.md` 5 章）、日本時間のツールチップ
- スマホ（768px 未満）と PC の 2 つのレイアウト、画像ビューア、確認ダイアログ、通知
- 未ログインで認証が要る画面を開くと `#/login?next=` へ、ログイン後に戻る

## 再現していないこと

プロトタイプとして割り切った点。本物のアプリとの違いはここにある。

| 項目 | プロトタイプ | 本物のアプリ |
| --- | --- | --- |
| 通信 | 無い。`store.js` の関数を同期で呼び、読み込み中の表示を見せるために 200 ms 待つだけ | HTTP で API を呼ぶ |
| バックエンド・DB | 無い。データは `localStorage` | Spring Boot と PostgreSQL |
| 認証 | ログイン状態は `localStorage` の `rt.session` だけ。JWT もリフレッシュトークンも無い | JWT とリフレッシュトークン |
| パスワード | **平文で `localStorage` に入れている。プロトタイプだけの扱い** | BCrypt でハッシュにして保存 |
| 画像の保存先 | `localStorage` に data URL で入れる（S3 相当は無い） | Amazon S3。元のファイルを保存し、JPEG の GPS 情報を取り除く |
| 画像の画質 | ブラウザで長辺 1280px に縮めてから保存する。JPEG と WebP は品質 0.85 で作り直し、PNG は PNG のまま、GIF は PNG に変える（動きは失われる）。アイコンも同じで 1280px まで | 原本のまま |
| 画像の容量 | `localStorage` の上限（オリジンあたり約 5 MB）に収まる範囲だけ。超えると「プロトタイプの保存容量を超えました。小さい画像を選ぶか、見本データに戻してください」と出る。写真の PNG は縮小しても 2 MB 前後あり、数枚で上限に届く（JPEG なら 1 枚 0.5 MB 前後） | 上限は 1 枚 5 MB と 4 枚まで |
| 回数制限 | 無い | ログインと登録に回数制限がある（nginx） |
| URL | `#/` で始まるハッシュ。ハッシュが不正な形（`#/users/%` など）だと真っ白になる | パス（`/users/alice`）。存在しない URL は「見つかりません」の画面 |
| id | 連番の整数。全テーブルで 1 つの `nextId` を共有するので、投稿の id は 1〜60 にならない | UUID v7 |
| タブの切り替え | ホームのタブを切り替えるたびに読み直す | TanStack Query のキャッシュで、切り替えでは読み直さない |
| データの共有 | ブラウザの中だけ。別の人や別のブラウザには見えない | 全員で共有 |

## 既知の粗さ

直していない点。仕様の確認には支障が無いので、そのままにしてある。驚かないように書いておく。

- 存在しない投稿の id（`#/posts/9999`）は、「見つかりません」の画面ではなく「ページが見つかりません」の画面になる
- 画像が 1 枚の投稿は、横長の枠（16:9）に切り取って表示する。縦横比は保たない
- 投稿の本文の余白を押しても投稿詳細へ移らない。移れるのは時刻とコメント数だけ
- ダイアログから投稿すると、表示中の画面を描き直す。ホームの上部のフォームに書きかけの本文があると消える
- 不正な形のハッシュ（`#/users/%` など）は真っ白になる
- `localStorage` の中身が壊れていると真っ白になり、画面の「見本データに戻す」に届かない。コンソールで `localStorage.clear()` してリロードする
- 時刻のリンク（21px の高さ）と、投稿詳細のいいね数のリンク（32px の幅）が、44px 四方に届かない
- スマホ幅で、一覧の末尾に近いところでは右下の「＋」ボタンが、右端のフォローボタンに重なる
- 投稿詳細の絶対時刻が長いので、スマホ幅では「@ユーザー名 ·」の次の行に回る
- アイコンを変えても、左ナビの自分のアイコンは次に画面を移るまで変わらない
- 編集ダイアログで保存容量を超えたときの文言が「小さい画像を選ぶか」になる（編集では画像を変えられない）
